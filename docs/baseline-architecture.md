## 0. 產品目標（北極星）

打造**最普及 × 最精準**的情緒掃描 app。兩者看似衝突，靠「多模態量測 + 分層精準度 + 跨模態校準」同時達成：
- **普及**：只有手機也能用（臉部掃描，零配件）
- **精準**：願意的人可用手指、手錶、胸帶逐級提高可靠度

---

## 1. 量測模態與精準度階梯（Modality Precision Ladder）

由準到普及（**HRV 可靠度**排序，HRV 是基線核心）：

| 階梯 | 模態 | 技術 | HRV 可靠度 | 角色 |
|---|---|---|---|---|
| 1（最準）| 胸帶 Chest strap（如 Polar H10）| ECG | Gold standard | 校準錨點 / 最高真值 |
| 2 | 手指 Finger | 接觸式 PPG（後鏡頭）| 高（靜止下佳）| 精準掃描 / phone-only 的最佳 HRV |
| 2 | 手錶 Garmin / Apple Watch | 光學 PPG | 中高 | 連續背景 / 校準源 |
| 3（最普及）| 臉部 Face | rPPG（前鏡頭）| 中（靜止放鬆下堪用，較吵）| 日常掃描主力 |

**關鍵事實（已查證實證）**
- 靜止下，臉部 rPPG 與手指 PPG 的**心率（HR）**幾乎一樣準（對照 ECG RMSE ≈ 1 bpm）。
- **HRV** 則手指明顯較穩；臉部 rPPG 訊號較弱、受光線/膚色/動作影響大。
- 臉部 rPPG 的 HRV 在「靜止、放鬆、標準流程」下可達堪用（這正是建立基線的場景），但仍比接觸式吵。
- 胸帶 ECG 是 HRV 真正的 gold standard，**比手指還準**。

---

## 2. 核心原則：Per-Modality Baseline + Cross-Modal Calibration

> **這是整個架構最重要的一條，違反它會悄悄破壞情緒分數的可信度。**

### 2.1 為什麼不能「一條基線通用」
不同模態的 HRV 差異**不是單純隨機雜訊，而是系統性偏移**（臉部與指尖的血流波形型態、訊號來源不同，會差一個固定的量）。

→ 若用「手指基線」去比「臉部掃描」，那個固定偏移會被演算法**誤判成情緒/生理變化**，且每天同方向偏移，難以察覺。
→ 隨機雜訊可用多次平均解決；**系統性偏移只能靠校準**。

### 2.2 規則
1. **每種模態各有自己的基線**（`baseline[modality]`）。
2. **掃描一律 like-for-like**：臉掃比臉基線、手指掃比手指基線。
3. **用較高階模態校準較低階模態的偏移**（offset），讓低階基線逐步逼近真值。
4. 比較與情緒分數計算，永遠在「同模態」或「已校準到共同參考」的前提下進行。

## 3. 資料結構建議（OPEN：實作時定稿）

```
BaselineRecord {
  modality: "face_rppg" | "finger_ppg" | "garmin" | "apple_watch" | "chest_strap"
  metrics: { hr_bpm, hrv_rmssd_ms, hrv_sdnn_ms, resp_brpm, ... }
  quality: 0–100              // 訊號品質
  created_at, updated_at
  sample_count                // 累積樣本數（基線會隨用越準）
}

CalibrationOffset {
  from_modality, to_modality  // 例：face_rppg → finger_ppg
  metric                      // 例：hrv_rmssd_ms
  offset                      // 該使用者在兩模態間的系統性差值
  confidence, measured_at
}
```
- 比較時：`adjusted = scan_value − offset(scan_modality → reference_modality)`，或直接比同模態基線。
- 基線應**隨資料累積持續更新**（rolling baseline），sample_count 越高越穩。

## 4. 流程設計（採用模型 B：臉基線為主 + 手指為可選精準提升）

> **設計取捨**：核心情緒訊號是「偏離你自己的基線」，只需**同模態基線**即成立。因此日常方法（臉）的基線是**必須**，手指基線是**加分**。為了「最普及」，onboarding 走最低摩擦：只建臉基線，手指轉為之後的智能校準提醒。被否決的「雙基線（手指+臉都做）」摩擦過高、新手流失風險大。

### 4.1 首次 Onboarding — 只建臉部基線（Face Baseline）
1. 第一次使用**直接進臉部基線**（星塵靈魂頁，rPPG，約 60 秒）。
2. 因為日常掃描就是臉，臉掃比臉基線是 **like-for-like**，情緒訊號當下就有效——不需要等手指校準。
3. **不要**在 onboarding 強制手指。手指改由 §4.3 的智能提醒在對的時機建議。

> 文案修正：**移除「選擇你的建立方式 / 兩種方式都會建立同樣的基線」這種二選一、對等的說法**（科學上不成立、且與本架構衝突）。改為單一主路徑的誠實表述，例如：「先建立你的臉部基線，日常掃臉就能讀出偏移；想更準時再用手指校準」。

### 4.2 日常使用 — 臉部為主
- 主路徑：星塵靈魂頁掃臉（rPPG）→ 比**臉部基線**（like-for-like）。
- 高壓 / 需要決策時：切**手指**掃描（更準的 HRV）→ 比手指基線。

### 4.3 手指 = 可選精準提升（智能提醒，非必經）

手指掃描的**兩層價值**（提醒文案應強調這點，使用者才有誘因）：
- **當下層**：對 phone-only 使用者，那一次掃描的 HRV 品質直接提升（手指 PPG > 臉部 rPPG）。
- **系統層**：順便重新量到 face↔finger 偏移量，更新 `CalibrationOffset` → 讓**之後每一次臉掃都更準**。
  → 一句話：一次手指，不只「那次準」，是「往後的臉掃都更準」。

**智能提醒的三個觸發時機**（看「現在需不需要」，不是只看「有沒有空」）：
1. **臉基線還不夠穩**：剛 onboarding 完、臉基線 `sample_count` 偏低、或連續幾次臉掃 `quality` 偏低 → 最該提醒。
2. **高壓 / 決策時刻**：使用者要做重要決定時，主動建議切手指（更可靠的 HRV）。
3. **定期校準**：距上次手指校準過久（如數週）→ 輕量提醒一次，讓偏移量保持新鮮。

**自動校準（無需提醒）**：每當更高階模態在場（胸帶 > 手指/手錶），自動更新 face 基線 offfset。優先序：**胸帶（ECG）> 手指/手錶 > 臉**。

### 4.4 提醒設計的鐵則（避免嘮叨）
臉部自我比對本就堪用，手指是「錦上添花」不是「不做就壞」。因此：
- 提醒**低頻、可永久關閉**，語氣是「想更準的話」而非「你必須」。
- **絕不**讓使用者覺得「不掃手指 app 就不準 / 在催我」——那會傷害「普及、無壓力」的核心定位。
- 預設安靜；只在 §4.3 三觸發點且間隔足夠時才出現。

## 5. 已知資料問題（待查，與基線架構獨立但相關）
- ⚠️ 基線結果頁曾顯示 **HRV 536 ms**：對 RMSSD 不合理（靜息正常約 20–100 ms）。需查計算邏輯——可能是單位、欄位綁錯或演算法問題。
- ⚠️ 基線結果頁「**呼吸節奏 0 次/分**」：疑似未計算 / 取值 bug，或該模態本就無此指標卻仍顯示 0。

## 7. 給 AI 協作者的快速守則（TL;DR）
1. **掃描比基線，一律同模態**；跨模態一定先校準。
2. 模態精準度：**胸帶 ECG > 手指/手錶 PPG > 臉部 rPPG**（尤其 HRV）。
3. 臉 = 普及主力（onboarding 只建臉基線）；手指 = 可選精準提升（智能提醒，非必經）；外接裝置 = 校準錨點。
4. Onboarding 採**模型 B**：不要做「二選一」或「強制雙基線」；第一次只建臉基線（見 §4.1）。
5. 手指掃描有「兩層價值」：當下更準 + 校準臉基線讓往後臉掃更準（見 §4.3）。提醒要克制、不嘮叨（§4.4）。
6. 別寫「兩種方式建立同樣基線」這種話。
7. 動到 HRV / 基線 / 分數計算 / onboarding 流程前，先回來讀本文件。
