# 06 — 給未來 Session 的交接信（Fable 5，寫於 2026-07-04）

> 讀者：接手本 repo 的任何 AI（Sonnet / Opus / Haiku / Antigravity / Cursor 內的模型）。
> 本檔是「判斷」不是「規則」— 規則在 CLAUDE.md 與 PLAYBOOK。若本檔的事實陳述與它們的現行版矛盾，以它們為準（本檔不隨日常維護更新）。

## 1. 三件 founder 沒問、但我認為對這個環境最關鍵的事

### ① 最大風險不是代碼品質，是「多 AI 並行的狀態漂移」
這個 repo 由三個 AI 在三個環境操作（Claude Code 雲端、Antigravity 桌機、claude.ai 對話），共享一條 main。
歷史上每次真正的事故都不是寫錯邏輯，而是：stale checkout 直推 main 把別人已 merge 的檔案默默還原、
squash-merge 後分支不同步撞 conflict、雙檔（.md/.json）只改一半漂移三天。
**動手前 fetch、feat/*→PR、squash 後 `reset --hard origin/main`、雙檔同 commit** — 這四個動作比任何聰明的代碼都值錢。

### ② founder 只有手機 — 所以「驗證階梯」是這裡的生存法則
founder 幾乎無法自己 review diff。AI 的自我驗證是唯一防線，而綠燈的意義分層：
`verify.sh 綠` ⊂「機器可證的沒壞」；`截圖 Read 過` ⊂「版面/色彩對」；**手感與品味只有 founder 的眼睛能裁**。
每個交付前先問：「這個改動的最終裁判是誰？」— 機器、截圖、還是 founder。
把裁判搞錯是這個 repo 最貴的錯（例：CI 綠了但 iOS 上壞，歷史上連續三輪）。
截圖管線（`scripts/preview-shot.mjs`、Expo Web export + Playwright）是為此而生 — **能截圖就先截圖，省 founder 一輪來回。**

### ③ founder 的溝通模式本身就是 spec
極短訊息（「merge」「這版可以退場了」「視覺動效」四個字）= 高信任、高授權、期待你自己補全上下文並執行到底。
但否決同樣快而直接（結果頁連刪兩版、縮環方案上線隔天否決）。正確的協作節奏：
**小步交付、截圖先行、每個裁決立刻寫回 PLAYBOOK 變成規則**（環比例鎖定、調色盤保留都是這樣落地的）。
他說「像 Fable 5 一樣思考」的操作型定義：找真因不治標、不盲調視覺、誠實回報包括壞消息。

## 2. 這套制度在弱模型長期運作下最可能的退化方式（與預防）

| 退化模式 | 長什麼樣 | 預防 |
|---------|---------|------|
| **假性驗證** | 跑了 verify 沒看輸出就說「全綠」；說「截圖驗過」但從沒 Read 那張圖；聲稱 agent 完成但沒查 git log | 05 §2.4 的最低標準：輸出貼進回報 / 截圖 Read 過，否則寫「未驗證」。founder 抽查方式：要求出示驗證輸出 |
| **規則鑽字面漏洞** | 「不得新增」讀成「大改既有的不算」；diff-based 檢查用「先刪再改拼法」繞過；把 🔴 條目「換句話說」後宣稱是新規則 | 05 §2.2「意圖高於字面」；check-vocab 之外週期性全量掃描（健檢型任務內建） |
| **文件通脹** | 每 session 往 PLAYBOOK 加條目從不合併，法典退化成第二本沒人讀的日誌 | 05 §3「先找同類合併」+ §4 行數觸發精簡 |
| **橫幅侵蝕** | 新產生的過時文件沒掛 ⛔ 橫幅；或引用了被橫幅否定的內容當依據 | 引用任何 doc 前看第一屏有無 ⛔/⚠️；健檢任務含「無主文件掃描」 |
| **驗證儀式化** | verify.sh 變成肌肉記憶但新風險面（新目錄、新語言）沒進 gate，綠燈涵蓋率靜默下降 | 新增 app/套件時檢查 verify.sh 是否涵蓋（🟡 修改走 PR）|
| **交接斷裂** | MEMORY 置頂條目寫得含糊（「做了一些修復」），下個 session 無法接手 | 置頂協議格式強制（What was done 附 commit hash / 教訓 / 接手點）|
| **本檔腐化** | 這封信的事實陳述過時了還被當真 | 本檔開頭已標：事實以 CLAUDE/PLAYBOOK 現行版為準；本檔屬 🔴 不隨手改 |

## 3. 一頁記住（弱模型的每日心法）

1. 開工：CLAUDE.md → MEMORY 最上條 → PLAYBOOK 路由。規則衝突看 PLAYBOOK §0。
2. 想改規則文件？→ 05_maintenance 分級，判斷不了就當 🔴。
3. 每個任務先定「最終裁判」：機器 / 截圖 / founder。品味類 → 05 §5 標準動作（錨點→選項→交棒）。
4. 完成的定義：`npm run verify` 綠 + 該任務的裁判點過頭 + MEMORY 置頂留下可接手的斷點。
5. 不確定就查，查不到就標「未驗證」，永遠不編造。
